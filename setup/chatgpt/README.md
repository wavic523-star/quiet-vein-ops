# Настройка ChatGPT-стороны проекта

Для владельца. Порядок важен: сначала дайджесты, потом создание GPT.

## Шаг 1. Дайджесты четырёх чатов (один вечер, ~30 мин)

1. Открой в ChatGPT обычный чат с доступом к GitHub (коннектор GitHub включён).
2. Вставь промпт из `DIGEST-PROMPT.md` четыре раза — по одному на файл (подставь `<ИМЯ>` и `<ЦЕЛЬ>` из таблицы внизу промпта). Лучше — отдельный чат на каждый файл, чтобы не упираться в контекст.
3. ChatGPT запишет четыре файла в `onboarding/`: `dev.md`, `story.md`, `lore.md`, `promo.md`. Проверь, что они появились в репозитории.

## Шаг 2. Четыре Custom GPT

Для каждой строки таблицы: chatgpt.com → Explore GPTs → Create → вкладка Configure.

| GPT | Файл настройки | Knowledge-файлы (скачать из репо и загрузить) |
| --- | --- | --- |
| **QV Сюжет** | `gpt-story.md` | `rules/story.md`, `rules/00-general.md`, `README.md`, `onboarding/story.md` (после шага 1) |
| **QV Лор** | `gpt-lore.md` | `rules/lore.md`, `rules/00-general.md`, `README.md`, `onboarding/lore.md`, `onboarding/readme-agents.md` |
| **QV Продвижение** | `gpt-promo.md` | `rules/promo.md`, `rules/00-general.md`, `README.md`, `onboarding/promo.md` |
| **QV Лаборатория** | `gpt-lab.md` | `rules/lab.md`, `rules/00-general.md`, `README.md` |

В каждом файле `gpt-*.md` три блока: **Инструкция** (вставить в поле Instructions), **Knowledge** (список файлов выше), **Стартовый промпт** (вставить первым сообщением в чат с GPT — он выполнит старт по шине).

Возможности GPT: включить **Web Browsing**; Code Interpreter не нужен. GitHub — через стандартный коннектор (в чатах с GPT он доступен, если включён в настройках аккаунта: Settings → Connectors → GitHub). Если коннектор внутри GPT недоступен — работаем через обычные чаты с коннектором, а GPT используем как «личность» с knowledge-файлами.

## Шаг 3. Запуск

1. В каждой GPT вставь её стартовый промпт.
2. «QV Сюжет» — первым: у него горящие сроки (см. M-0161: слой оформления просрочен 22.11; спецификация подземелий 3–4 + вводная + таблица продаж — 24.11; canon отстал).
3. Сообщи Kimi («Синхронизация»), что чаты подняты, — сверка.

## Как пишется в репозиторий

ChatGPT коммитит прямо в `main` через GitHub-коннектор с префиксами коммитов (`[bus]`, `[onboarding]`, `[lab]`…). Перед записью — обновить локальную картину (перечитать изменённые файлы). Коллизии почти исключены: чаты работают последовательно под контролем владельца; при конфликте — правило в `README.md` (создать файл с суффиксом `-b` и сообщить «Синхронизации»).
